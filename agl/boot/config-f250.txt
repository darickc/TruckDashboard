# Original 7" touchscreen on DSI0 (CAM/DISP 0): the port Raspberry Pi OS
# found it on (rp1 dsi 1f00118000, touch on I2C bus 10; bench-log 2026-11-02
# and 2026-11-06). Without ",dsi0" the overlay drives DSI1, and the panel
# stays dark. Includes the edt-ft5406 touch driver. Drop ",dsi0" only if the
# ribbon moves to CAM/DISP 1 (H3).
# AGL's own config.txt only loads vc4-kms-v3d-pi5,cma-256 and leaves the panel
# off, so this line is what turns the display on.
dtoverlay=vc4-kms-dsi-7inch,dsi0

# Pi 5 onboard RTC: charge the rechargeable cell on J5 (H20). Uncomment once
# that cell is fitted: only a rechargeable one, never a CR2032. Applied and
# read back as 3000000 on AGL 22.0.1 (bench-log 2026-11-06). Without a cell
# the clock starts at 1970 on every cold boot until network time sets it.
#dtparam=rtc_bbat_vchg=3000000

# HiFiBerry DAC8x (ADR-0014). The overlay ships in the Vimba 22.0.1 image.
# Uncomment once the HAT is fitted: the overlay claims BCM18-27.
#dtoverlay=hifiberry-dac8x

# Camera switch (ADR-0024, ADR-0025): five contacts to ground, one gpio-key
# overlay each. The kernel turns a contact into a key on its own input device;
# power-manager reads and debounces them. gpio_pull=2 is the pull-up (per the
# overlay's source); active low is its default. Keys F13-F17, because nothing
# in the UI acts on them (arrow keys would move its focus).
# Pins: docs/wiring/power-and-inputs.md#camera-switch; clear of the DAC8x
# (BCM5, BCM18-27). Never leave out keycode=: the overlay's default is
# KEY_POWER (116), and a camera press would shut the Pi down. Unconnected
# pins just sit pulled up. UNVERIFIED on the Pi 5: bench checks 8-9 in the
# wiring doc, then `journalctl -u f250-power-manager`.
dtoverlay=gpio-key,gpio=12,keycode=183,label=CAM_LEFT,gpio_pull=2
dtoverlay=gpio-key,gpio=13,keycode=184,label=CAM_RIGHT,gpio_pull=2
dtoverlay=gpio-key,gpio=16,keycode=185,label=CAM_BACK,gpio_pull=2
dtoverlay=gpio-key,gpio=6,keycode=186,label=CAM_FORWARD,gpio_pull=2
dtoverlay=gpio-key,gpio=17,keycode=187,label=CAM_PRESS,gpio_pull=2

# NVMe HAT on the Pi 5's external PCIe connector. Uncomment once the HAT is
# fitted: until then it is one more unknown on the first AGL boot. The
# firmware is reported to turn PCIe on by itself for HAT+ boards with an ID
# EEPROM (unverified); this line turns it on for any board. The NVMe and Pi 5
# PCIe drivers are built into the 22.0.1 kernel, and pciex1 is a parameter of
# its bcm2712-rpi-5-b.dtb (checked in the image files, 2026-11-06). Gen 2 (the
# default): Gen 3 (pciex1_gen=3) isn't certified.
# Using the drive: DATA_DRIVE in /etc/default/f250 (docs/setup/agl.md).
#dtparam=pciex1

# CAN: nothing here. The USB adapter (gs_usb, ADR-0012) needs no overlay; the
# mcp251x HAT lines in AGL's config.txt stay commented out.
